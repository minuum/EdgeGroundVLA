# 정지 정책 설계 — near 규칙과 헤드 정지를 섞기 (계획서, 승인 대기)

작성 2026-11-17 · 상태: **승인 전 — 코드·서버 변경 없음** · 관련: `plan_20261115_a3_improvement.md` §12, CH82, `_received_1116_eg2_14/`

## 0. 정정 (이전 설명 수정)
이전 답변에서 "헤드 출력 크기가 0.2 미만이면 정지"라고 했다. 컨트롤러 코드(`robovlm_nav/serve/egvla2_only_logic.py`)를 다시 읽으니 **헤드의 정지는 기본적으로 래치되지 않는다**.
- `stop_debounce=0`(기본)이면 헤드가 정지를 내도 STOPPED 래치가 걸리지 않고 **이동 0(idle)** 이 된다. idle이 `idle_max_frames`(20) 연속이면 안전망으로 STOPPED(idle_timeout).
- 헤드 출력이 다시 커지면 로봇이 다시 움직일 수 있다.
- 배포 서버(soda)의 실제 `stop_debounce`·`idle_max_frames` 값은 **이 저장소에서 확인하지 못했다**(미확인). 로봇 쪽에서 확인해야 한다.
- 따라서 11/16에서 `near_area` 규칙이 걸리지 않은 세션(바구니 10/15, 책상 15/15)은 "헤드 정지"가 아니라 "헤드 idle 또는 운영자 정지"로 끝났을 수 있다. 어느 쪽인지는 세션 JSON의 `reason`으로 가려야 한다.

## 2. 현재 정지 구조 (코드 기준)
| 경로 | 동작 |
|:--|:--|
| 헤드 | 크기 <0.2이면 이동 0(idle). `stop_debounce`>0이면 연속 N프레임 후 래치. |
| near 규칙 | `bbox_area >= near_area`가 `near_frames`(2) 연속이면 STOPPED. 물체 구분 없음. |
| 안전망 | idle 20프레임 연속 → STOPPED, 탐색 40프레임 초과 → STOPPED. |
| 운영자 | 조이스틱 정지·성공 버튼. |

## 3. 설계안
공통: 헤드를 재학습하지 않는다. 컨트롤러 인자·분기만 바꾼다.

1. **물체별 near_area** — 지시어에서 물체를 구분해 임계값을 따로 둔다.
   ```python
   NEAR_AREA_BY_OBJECT = {"gray basket": 0.13, "brown wooden chair": 0.22, "small desk": 0.20}  # 자리표시값, 오프라인·실측으로 정한다
   near = NEAR_AREA_BY_OBJECT.get(phrase_key(phrase), default_near)
   ```
2. **다음 스텝 예측** — 직전 프레임 대비 증가량으로 다음 면적을 외삽해 임계값을 넘을 것으로 예측되면 지금 정지.
   ```python
   pred = area + max(0.0, area - self.prev_area)
   hit = pred >= near          # near_run 계산에 area 대신 pred 사용
   ```
3. **접근 감속** — 면적이 커질수록 gain을 줄여 스텝을 잘게 만든다.
   ```python
   r = clamp((area - a_slow) / max(near - a_slow, 1e-6), 0.0, 1.0)
   gain = 1.15 * (1.0 - (1.0 - gain_floor) * r)      # a_slow 이상에서 gain_floor(예 0.5)까지 선형 감소
   ```
4. **헤드 정지의 역할 제한** — 면적 바닥값(`head_stop_floor`, 예 0.15) 미만의 헤드 정지는 도착 판단으로 인정하지 않는다(출발 직후 망설임 방지). 바닥값 이상에서의 헤드 정지는 그대로 인정.

수정 예정 파일: `robovlm_nav/serve/egvla2_only_logic.py`(컨트롤러), 단위 시험, soda 패치 파일(별도 단계). 기본값은 현재 동작과 동일(옵션 끔)으로 둬서 승인 전까지 서버 동작이 바뀌지 않게 한다.
