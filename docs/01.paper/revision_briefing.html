"방향 대조 학습" 용어 재검토 — 문헌 근거

"방향 대조 학습"은 표준 용어가 아니라 우리가 만든 조합어이며, negative 샘플링 없는 고정 5-클래스 분류라 엄밀한 대조학습 정의에도 안 맞음. arXiv 원문 직접 확인 근거:

표현적합도근거
text-derived classifier ⭐ 가장 정확 CLIP §3.1.2: "the text encoder is a hypernetwork which generates the weights of a linear classifier..."
class prototype ⭐ 정확 CLIP 본문엔 없음(0건) — CLIP-S⁴(arXiv:2305.01040)가 출처: "For known classes, the prototypes are pre-computed and fixed... For unknown classes, learned during training"
cosine similarity + temperature ⭐ 메커니즘 그대로 CLIP §3.1.2 — 우리 코드와 1:1 대응(F.normalize→cosine→/τ→CE)

→ 추천 표현

"텍스트 앵커를 클래스 프로토타입으로 사용하는 방향 분류 학습(text-derived class prototypes)" — 단 우리는 text_proj도 함께 학습돼 프로토타입이 움직이므로 "fixed"는 빼고 쓸 것. VLA 계열에는 대응 용어 없음 (런타임에 언어를 쓰지 않는 우리 설계와 오히려 차별점).

Q1+Q2 통합 수정안 — §5.3 (HWP p231)

수정 전

...Stage 1에서 image_proj(0.262M)를 방향 대조 학습으로 학습하고 고정한다. 그리고 Stage 2에서 그 위에 MLP 헤드(0.866M)만 학습하는 구조이다. 전체 학습 파라미터는 1.128M이다.

🛡 격차 방어 — 프레임 정확도 ≠ 에피소드 성공률

본문 추가 문단 — Stage 1 vs Stage 2 일반화 격차 (§5.5 말미)

→ 그대로 복사해 붙이기

Stage 1과 Stage 2의 일반화 양상은 뚜렷하게 다르다. image_proj(Stage 1)는 학습 정확도 96.10% 대 검증 정확도 94.09%로 격차가 2.01%p에 불과하나, 행동 헤드(Stage 2)는 학습 91.44% 대 검증 74.04%로 격차가 17.40%p에 이른다. 즉 과적합은 파이프라인 전반이 아니라 Stage 2에 국한된 현상이다. 다만 이 격차가 실제 주행 성능을 제한하지는 않았으며, 실로봇 100회 시험에서 95%의 목표 도달 성공률을 확인하였다(IV장).

격차 배수(8.7배)는 클래스 수(5 vs 8)가 달라 과잉 해석으로 보일 수 있어 %p 병기만 권장.

  1. "Cosine 유사도" 박스 — 안에 식 그대로: s_j = f⊤e_j (j=1..5)
  2. "Temperature-scaled Softmax (τ=0.07)" 박스 — 온도 스케일링+softmax를 한 박스로 합쳐서: p_j = softmax(s_j/τ)
  3. "CE Loss" 박스 — L = -w_y·log(p_y)

"CLIP-style"이라는 수식어는 그림 라벨에는 넣지 않는다 — CLIP 논문을 있는 그대로 인용한 게 아니라(τ 고정 vs 학습 차이) 유사 메커니즘만 차용한 것이라, 그림에 박아두면 과잉 주장이 될 수 있음. "CLIP(Radford et al., 2021) 기반, 단 τ 고정"이라는 문구는 본문 캡션/문장에만 남기고, 그림 라벨은 기능 이름(Cosine/Softmax/CE Loss)만 쓰는 역할 분담 권장. (위 머메이드 다이어그램의 L4 서브그래프가 이 3박스 축약의 예시)

오해 방지: bbox_scale은 카메라 화면에 그려지는 실제 검출 박스의 픽셀 크기와는 무관하다. OWL-v2가 내놓는 bbox 4채널(cx, cy, area, has_bbox) 숫자 값 자체에만 배수를 곱하는 입력 특징 스케일링이며, 카메라가 보는 이미지나 화면상 박스 표시는 전혀 바뀌지 않는다.
