# 로드맵: Edge-grounding-VA → Edge-grounding-VLA

> 작성 2026-08-04 · 출처: 미팅 노트 (18:33~18:45)
> 상태: **방향 합의됨 · 단 3개 항목이 자체 실측과 충돌 → 재검토 필요**

---

## 1. 합의된 포지셔닝

| 항목 | 내용 |
|---|---|
| **현재** | **Edge-grounding-VA** — 언어 조건화 없음. OVD(OWL-v2) + 비전 + 이산 액션 헤드 |
| **추후** | **Edge-grounding-VLA** — language를 넣고 하나의 VLA 모델로 통합 |
| **경쟁 상대 아님** | MobilityVLA와 정면 경쟁하지 않음 |
| **차별 지점** | **일반적이지 않은 경우에 적용하는 VA 시스템** — 엣지 제약 하에서 동작하는 것이 핵심 |

**Kosmos-2를 선택한 이유 (논문에 쓸 근거)**
수많은 인코더 중 Kosmos-2를 고른 것은 **선행연구 RoboVLMs에서 Kosmos-2를 썼을 때 가장
효과가 좋았기 때문**이다. 임의 선택이 아니라 선행연구의 실측 결과를 승계한 것.

> ⚠️ 서술 주의: RoboVLMs는 **선택 근거**로 인용하는 것이고, 현재 구현에 RoboVLMs 코드는
> 포함되지 않는다(CH65 / 모델 구조 자료 7절 참조). "RoboVLMs 기반"이라고 쓰면 사실과 다르다.

---

## 2. 목표 구성 (추후)

```
OWL-v2 (그라운딩)  +  Kosmos-2 backbone (비전 + 언어)  +  π0 계열 Flow Matching 액션 헤드
```

- 액션 출력을 **이산 8클래스 → 연속형**으로 전환
- 언어 부분 파라미터를 줄여 **1B 정도**로
- OWL-v2 레이턴시는 **양자화**로 해결

---

## 3. ⚠️ 자체 실측과 충돌하는 3개 항목

로드맵을 그대로 진행하면 이미 측정으로 기각된 선택을 반복하게 된다. **폐기하자는 게 아니라,
"왜 이번엔 다를 것인가"를 먼저 답해야 한다는 뜻**이다.

### ① OWL-v2 양자화 — 검출률을 파는 트레이드 (CH64 64-16, 65)

| 항목 | fp32 | fp16 |
|---|---|---|
| 지연 (Jetson 실측) | 1901.7ms | **962.1ms (1.98배↑)** |
| has_bbox 검출률 | 100%(기준) | **90.0% (−10%p)** |
| 좌표 정확도 | — | 차이 0.0001~0.0002 (불변) |

문제는 **검출률이 곧 실기 성공률**이라는 점이다 — gnd%≥80이면 주행 성공 98.8%(79/80),
80% 미만이면 51.2%(CH64 64-18). 즉 양자화는 **성패를 가르는 그 변수 하나를 팔아서
속도를 사는** 구조다. 게다가 threshold 완화와 병용하면 손실이 겹친다.

**대안 (이미 검증됨)**: Kosmos-2 patch 피처 위 0.279M heatmap 헤드로
검출 지연 1901.7ms → **53.8ms (35.3배↓)**, cx MAE 0.0020 (CH65 65-5).
양자화(1.98배)보다 **18배 더 큰 개선**이고 검출률 손실이 없다.
단 `has_bbox` 판정이 미해결이라 negative 데이터 확보가 선행 조건(CH65 65-6).

→ **권고: 양자화 대신 특화 검출기로 대체하는 경로를 우선 검토.**
양자화를 쓴다면 "검출률 −10%p를 어떻게 보상하는가"에 답이 있어야 한다.

### ② 이산 → 연속(π0 Flow Matching) — 이 규모에서 기각됨 (CH63 63-6)

exp73에서 4개 헤드를 같은 조건으로 비교한 실측:

| 헤드 | best (225ep, pg448) |
|---|---|
| **mlp (이산)** | **77.9%** ← 1위, 현재 배포 |
| cxgeom (이산) | 76.6% |
| contreg (연속, 단일회귀) | 74.7% |
| transformer (이산) | 72.0% |
| **flow (연속, MoNa-pi 경량판)** | **72.0%** (owl 71.3%) |

자매 프로젝트 MoNa-pi(π0 계열 풀 구현, AdaLN-Zero)도 closed-loop **45.8%**였다.
결론은 **"헤드를 연속/flow로 바꾸면 저절로 좋아진다"는 가설이 이 데이터 규모(225ep)에서
기각**된 것 — ODE 적분·velocity field 학습의 이점보다 소규모 데이터에서의 최적화 난이도가
더 크게 작용했다.

→ **권고: 연속형 전환은 데이터 규모 확대와 묶어서 계획.**
225ep에서 다시 시도하면 같은 결과가 나올 가능성이 높다. 또한 로봇 펌웨어가
**속도 크기를 무시하고 방향만 사용**(상수속도 구조, soda 확인)하므로,
연속 출력의 이점이 하드웨어 단계에서 잘려나가는 문제도 함께 풀어야 한다.

### ③ 언어 1B로 축소 — 방향은 맞지만 현재 상태와 정합 필요

현재 Kosmos-2 언어 디코더 1.361B는 **호출이 0회**이고, 이번에 **로드 자체를 제거**해
peak host RAM을 10.59GB → 3.20GB(−70%)로 줄였다(모델 구조 자료 2절).

즉 지금은 "언어를 안 쓰는 대신 RAM을 확보한" 상태다. VLA로 가면 그 RAM을 다시 쓰게 된다.

→ **권고: "언어를 넣어서 무엇이 좋아지는가"를 먼저 정량화.**
V5에서 text attention이 0.000%였고(Exp17~41C, head-only에서도 재현) 프롬프트를
어떻게 바꿔도 방향 정확도가 개선되지 않았다. **언어 조건화의 이득을 보일 수 있는
과제 설계**(예: 다중 객체 중 지시문으로 타겟 선택)가 없으면 파라미터만 늘어난다.

## 4. 정리 — 진행 순서 제안

| 순위 | 항목 | 근거 |
|---|---|---|
| 1 | **특화 검출기 완성** (negative 확보 → has_bbox 해결) | 35.3배 개선이 이미 검증됨. 양자화보다 우선 |
| 2 | **기구 편향 검정** (주행 불필요) | CH66 미검증 항목. 소프트웨어로 못 고치는 부분 선별 |
| 3 | **데이터 규모 확대** (트랙C 등) | ②의 전제 조건 |
| 4 | 언어 조건화 과제 설계 | ③의 전제 조건 |
| 5 | 연속형 액션 헤드 | 3이 선행돼야 함 |

**엣지 목표에 가장 빠른 경로는 1번**이다. 검출 단계가 전체 지연의 97%를 차지하므로,
여기서 35배를 줄이면 나머지 최적화는 부차적이 된다.

## 5. 논문 프레이밍에 쓸 문장 (초안)

- 현재 시스템은 **VLA가 아니라 "오픈 보캐블러리 검출 + 경량 액션 헤드"** 다 — 언어 디코더
  호출이 0회임을 실측으로 확인했다(모델 구조 자료 1-2절).
- 이 구조를 택한 경위 자체가 기여다: E2E VLA(Kosmos-2 + LoRA)에서
  **text attention 0.000%** 를 확인하고 언어 경로를 이탈했다.
- Kosmos-2 선택은 선행연구 **RoboVLMs의 인코더 비교 결과를 승계**한 것이다.
- 포지셔닝은 MobilityVLA 대체가 아니라 **엣지 제약 하의 특수 상황용 VA 시스템**이다.
