## 질문
모듈형은 박스가 틀리거나 사라지면 하류가 틀린다(오류 전파). 우리 헤드는 이미지 특징 768-d도 직접 받는다(반E2E). **박스가 훼손됐을 때 이미지 경로가 얼마나 방향을 유지하나? 그리고 박스 훼손 증강으로 학습하면 더 좋아지나?**

## 훼손 조건 (평가 프레임의 현재 박스에 적용, 문구는 기준 `gray basket`)
| 조건 | 내용 |
|:--|:--|
| clean | 원래 박스 |
| drop50 | 프레임의 50%에서 박스 제거(검출 실패, 창 전체 0) |
| drop100 | 전부 제거(박스 없이 이미지만) |
| jitter | cx에 σ=0.15 가우시안, 면적 ×logN(0,0.3) (불안정한 검출) |
| wrong | cx를 1−cx로 반전(반대편 오검출 — 가장 위험) |

## 변형 (학습 어휘·프레임 간격 9·3분할×시드3·A3 학습법 동일)
- **V0**: 이미지 전용, 박스 드롭아웃 30% (A3 방식 = 현재 배포 방식)
- **V0R (보완안)**: V0 + 박스 훼손 증강. 학습 중 샘플별로 제거 30% · jitter 20% · 반전 10%를 적용하되 **정답은 훼손 전 박스 기준 서보 라벨 그대로** → 박스가 의심스러울 때 이미지 특징에 의존하도록 학습
- **V4**: T4와 같은 텍스트 조건화(문구 40+부정 20%), 기준 문구로 평가
- (T5 토큰 캐시가 끝나면) **V5** 추가

## 지표
사람 첫 스텝 대비 방향 오차(°), 정지율(|명령|<0.2, 낮을수록 좋음; 정상 장면이라 멈추면 실패). 조건별 clean 대비 악화량(Δ°).

## 성공 기준(사전 선언)
- 보완안 V0R: wrong 조건에서 V0 대비 방향 오차 ≥5° 감소 **그리고** clean 방향 오차 악화 ≤1°.
- 달성 못 하면 "훼손 증강의 이득 없음 / 이미지 경로가 박스를 대체 못 함"으로 기록.
