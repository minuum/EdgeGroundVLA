11/13 물체 실험 — 원본 실기와 4개 모델을 같은 프레임에서 동시에

같은 사진을 5개 패널에 놓고 모델마다 낸 명령을 화살표로 표시합니다(위쪽=전진, 오른쪽=우측 이동, 화살표 길이=명령 크기, 크기 0.2 미만이면 '정지'). 키보드: ←/→ 프레임, Space 재생, [ ] 세션 이동.

읽을 때 주의 · 모델 패널은 열린 루프 재생입니다(기록된 프레임·박스를 모델에 넣은 첫 명령). 실제로 모델이 로봇을 몰았다면 이후 프레임이 달라졌을 것이고, 성공률을 예측하지 못합니다. '원본 실기'는 로봇에 실제로 나간 명령(H5 actions)이고, 'A3 재생'은 같은 프레임·박스를 이 서버에서 A3 헤드에 다시 넣은 값입니다실기 모델 원출력(분홍): 로봇 서버의 세션 JSON(chunk_first)에 남아 있는 후처리 전 모델 출력으로, 로봇 쪽에서 받은 3세션(바구니 성공 150911, 화분 실패 151741, 의자 출발 안 함 170121)에만 있습니다. 이 3세션에서 'A3 재생'과의 방향 차이 중앙값은 0.4~0.5°, 정지 일치 82~100%로, 재생이 실제 모델 출력을 잘 따라갑니다(표본 3세션). 확인된 사실(서버 코드 + 기록값): 서버의 구동 단계는 모델이 낸 명령을 방향만 취하고 길이를 버린 뒤 항상 1.15(gain)로 고정해 로봇에 보냅니다(egvla2_only_logic.py: '단위 방향 × gain 1.15'). 실제로 기록된 이동 프레임 623개의 명령 크기는 전부 1.149~1.151입니다. 모델 자체의 크기(재생 0.2~0.8)는 '움직일지 정지할지'를 가르는 데에만 쓰이고(0.2 미만이면 정지), 속도는 별도의 speed_scale이 맡습니다. 그래서 원본 실기는 '방향'과 '이동/정지'만 의미가 있고, 길이가 모두 같은 게 정상입니다. 아래 '서버 후처리' 버튼을 켜면 모델 패널도 같은 규칙(방향만, 길이 1.15)으로 그려 원본과 직접 비교할 수 있습니다(끄면 모델의 원래 크기). V4·V4R은 서빙 설계(박스 문구 gray basket 고정, 지시어는 문구 특징으로)로 10시드 평균, A3C-S30은 시드 0입니다(서빙한 적 없는 오프라인 변형). 박스는 면적으로 정사각형 근사.
