## 1. 현재 구조 (리서치)

- Flask 단일 라우트 `/` — 296카드 그리드 + 카드당 4모델 O/X 버튼, 클릭 즉시 `/api/label/<key>` POST
- 라벨 저장: `docs/v5/hsv_owlv2_preview_20260704/human_labels.json` — `{key: {h1:"ok"|"ng", h2:…, ow:…, pg:…}}`
- 예측 데이터: 같은 폴더 `meta.json` — 프레임별 4모델 `{cx, cy, x1..y2}` (미검출 시 null)
- 상단 sticky 바에 진행률 + 모델별 O비율 실시간 집계 (클라이언트 JS)

## 2. 제안: 상단 탭 4개 (라벨링 / 리포트 / 불일치 / 세션별)

단일 Flask 앱에 라우트 3개 추가. SPA 아님 — 각 탭은 별도 URL, 상단 탭바에서 이동.
모든 분석은 `human_labels.json` + `meta.json`을 요청 시점에 다시 읽어 계산 (라벨 진행 중에도 새로고침만 하면 최신).

### 탭 1: 라벨링 (기존 `/` 그대로)

변경 없음. 상단에 탭바만 추가.

### 탭 2: 리포트 (`/report`)

라벨 완료분 기준 모델별 종합 성적표:

| 항목 | 계산 |
|---|---|
| 정확도 | O / (O+X), 라벨된 프레임만 |
| 검출률 | meta에서 non-null 비율 (라벨 무관, 296 전체) |
| 미검출인데 실제로는 있었던 프레임 | 다른 모델이 O 받은 프레임 중 해당 모델 null |
| 세션별 정확도 미니 테이블 | 세션 × 모델 O비율 |

+ 하단에 결론 문장 자동 생성: "현재 라벨 기준 프리뷰 후보 1위: {모델} ({정확도}%)"

### 탭 3: 불일치 (`/disagree`)

사람이 봐야 할 프레임만 추려주는 필터 뷰 (라벨링 화면과 동일한 카드 UI 재사용):

- 필터 버튼: `미라벨만` / `모델간 O/X 갈린 프레임` / `PG가 X인 프레임` / `전원 X (진짜 안보임 후보)` / `cx 스프레드 > 0.15`
- cx 스프레드는 meta.json에서 계산 (라벨 없어도 동작) — 어긋난 프레임부터 우선 라벨하는 용도
- 카드에서 바로 O/X 클릭 가능 (기존 `/api/label` 재사용)

### 탭 4: 세션별 (`/sessions`)

세션 단위 요약 테이블 + 클릭 시 해당 세션 프레임만 필터된 라벨링 뷰:

- 행 = 세션, 열 = 프레임수 / 라벨완료수 / 모델별 O비율 / 4모델 cx 평균 궤적 스파크라인(inline SVG)
- 세션명 클릭 → `/?session=<stem>` (기존 `/` 라우트에 쿼리 필터 1개 추가)

### API 추가

- `GET /api/stats` — 탭 2·4가 쓰는 집계 JSON (서버 계산, 클라이언트는 렌더만)
- 기존 `/api/export`는 유지

## 3. 변경 파일

- `scripts/label/serve_hsv_owlv2_labeler.py` **단일 파일만 수정** — 라우트 3개 + 공용 카드렌더 함수 추출 + 탭바 HTML
- 신규 파일/의존성 없음, meta.json/human_labels.json 스키마 변경 없음

## 4. 트레이드오프

- 단일 파일이 ~400줄로 커짐 — 허용 (일회성 검증 도구, 배포 대상 아님)
- 서버측 집계 vs 클라이언트 집계: 탭2/4는 서버 계산 선택 — 296×4 정도는 요청당 수 ms, 코드가 단순해짐
- 스파크라인은 외부 라이브러리 없이 inline SVG — 조잡해도 추세 파악엔 충분
