MoNaVLA 모델 구조 & 학습 방식 정리

미팅 발표용 · 2026-08-01 기준 · 모든 수치는 코드/체크포인트에서 직접 측정한 실측값  |  근거 상세 → CH64
한 줄 요약 — 이 시스템은 VLA가 아니라 "오픈 보캐블러리 객체 검출 + 액션 헤드"입니다. 언어 디코더는 로드만 되고 한 번도 호출되지 않으며(실측), 실기 성패는 액션 헤드가 아니라 객체 검출 성공률이 결정합니다(gnd%≥80 → 98.8% 성공).

프레임 특징 벡터 — 260차원

FRAME_DIM = 4 + 256 = 260
  ├ bbox 4채널  : cx, cy, area, has_bbox   ← OWL-v2 출력 (area는 bbox_scale=3.0 배율 적용)
  └ 비전 256채널: Kosmos-2 vision_model(1024) → image_proj → L2 normalize

헤드 입력 : window=6 프레임을 flatten → (6 × 260) = 1560차원
헤드 출력 : 8클래스 로짓
has_bbox 채널의 의미 — 검출 실패 시 cx=0.5, cy=0.6, area=0.06의 고정 fallback 값이 들어가고 has_bbox=0으로 표시됩니다. 즉 헤드는 "지금 타겟을 못 보고 있다"는 신호를 입력으로 받습니다. 그런데 학습 데이터에는 has_bbox=False 프레임이 0.00%(0/16,599)여서, 모델은 이 신호에 대응하는 법을 배운 적이 없습니다(CH64 64-15). 실기에서는 이를 학습이 아니라 서빙 제어 로직으로 우회했습니다(4절).

관련해서 실제 사고가 한 번 있었습니다 — 전체 데이터 재학습판을 만들 때 학습 데이터 자체를 val로 써서 에폭을 고른 탓에 정확도가 94.5%로 부풀었고(정상 범위 75%), 별도 홀드아웃을 분리해 74.5%로 재학습해 교체했습니다.

hold-aware 학습 — 실서빙 주기를 학습에 반영

그라운딩이 ~2초 걸려서 실기 판단 주기는 6Hz가 아니라 약 1.3Hz이고, 그 사이 로봇은 직전 명령을 그대로 유지합니다(zero-order hold). 매 프레임 재판단을 가정한 학습과 이 조건은 어긋납니다. 그래서 stride=5마다 한 번만 판단하고, 라벨은 그 5프레임 구간의 다수결로 주는 방식으로 학습했습니다.

학습 방식HELD 조건 평가
연속(매 프레임) 학습7.1 ± 3.8%
stride5 입력만 적용24.2 ± 2.5%
hold-aware (구간 다수결 라벨)28.3 ± 3.8%
이 지표를 인용할 때 주의 — HELD 수치는 프레임 단위 판단 정확도 프록시이고, 실기 89%는 에피소드 도달 성공률입니다. 서로 다른 척도라 직접 비교할 수 없습니다(중간에 몇 스텝 틀려도 재검출로 보정되면 성공). 과거에 이 둘을 맞춰 해석했다가 잘못된 결론을 낸 사례가 있어 CH64 64-11을 철회했습니다.

4. 서빙 제어 로직 — 학습으로 못 고친 걸 여기서 막습니다

2절에서 말한 "has_bbox=False를 학습한 적이 없다"는 구조적 결함을, 재학습이 아니라 제어 계층에서 우회했습니다. 현재 적용 중인 설정:

설정역할
owlv2_thresh = 0.20검출 임계값 (0.25에서 하향 — 실측 검출률 1.71배)
force_reground_on_miss미검출 시 다음 스텝 캐시를 강제로 건너뛰고 재검출
회전 후 강제 재그라운딩시야가 크게 바뀐 직후 캐시 신뢰 금지
회전 0.4초 제한 + 자동정지회전 폭주 방지
연속 회전 차단같은 방향 회전 반복 잠김 방지
stop_mode = learned + 콜드스타트 가드 3프레임초기 프레임 오판으로 즉시 정지하는 것 방지
grounding_skip_n = 33프레임마다 1회만 신선 그라운딩(속도 타협)

실패의 정체 — "안 보인다"가 아니라 "경계에 걸린다"

미검출 프레임 197장을 로컬에서 재실행해 confidence를 확인했습니다:

로컬 score해석비중

0.01 ~ 0.10매우 낮음21.3%
0.10 ~ 0.20보이지만 임계값 바로 아래 — 지배 구간54.8%

6. 다음 단계 제안

  1. 언어 디코더 로드 제거 — 성능 변화 없이 1.82B → 0.46B (−74.8%). 가장 값싼 개선이고 즉시 가능.
  2. 도메인 특화 소형 검출기 직접 학습 — 범용 OWL-v2(1902ms)를 양자화로 깎는 방식은 부적절합니다. fp16은 1.98배 빨라지지만 검출률이 10%p 떨어지고, 위 발견대로 검출률이 곧 성공률이므로 성패를 가르는 변수를 팔아 속도를 사는 셈입니다. 우리 과제는 대상이 "회색 바구니" 하나로 고정되어 있어, 특화 검출기를 직접 학습하는 쪽이 속도·정확도 양쪽에서 유리합니다.
  3. has_bbox=False 상황 시범 데이터 수집 — 현재 0.00%인 미검출 상황에 사람이 정답 행동(탐색 회전/정지)을 시범해 학습에 포함. 지금은 제어 로직으로 우회 중인 부분을 모델이 직접 처리하게 함.
  4. 동일 위치 A/B 재측정 — 89% 개선이 체크포인트 교체 때문인지 임계값+제어로직 때문인지 아직 확정하지 못했습니다(두 변경이 서로 다른 위치에서 이뤄져 교란).
