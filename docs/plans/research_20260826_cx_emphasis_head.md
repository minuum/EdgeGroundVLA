# 리서치 — "cx를 강하게 반영하는 액션헤드" 이미 뭘 시도했나

## 핵심 발견: 이미 시도됐고, 효과가 제한적이었다

`scripts/train_exp73_stage1v3_heads.py`에 이미 cx(bbox geometric 신호)를 강조하는
헤드 2종이 구현·학습·평가까지 완료돼 있다 (`docs/v5/closed_loop_eval/exp73_trackA_heads.json`).

### 기존 결과 (그라운더별 3계열 비교)

| 조건 | mlp(baseline) | cxgeom | hybrid | transformer(배포) |
|---|---|---|---|---|
| owl/v6 | 77.74% | **78.13%**(+0.4p) | — | 74.93% |
| owl_trackF/v6 | 76.66% | 75.84%(-0.8p) | **76.96%**(+0.3p) | 71.84% |
| pg448/v6 | **77.87%** | 77.69%(-0.2p) | — | 74.54% |
| pg448_trackF/v6 | 77.39% | 76.18%(-1.2p) | **77.70%**(+0.3p) | 71.81% |
| pg448/v6v5 | **76.98%** | 77.04%(+0.1p) | — | 72.94% |

- **cxgeom**: MLP trunk(flatten window) + bbox 4채널 전용 별도 브랜치(32d) → concat.
  cx를 명시적으로 별도 경로로 태워서 손실되지 않게 하자는 아이디어. 결과: 조건에 따라
  +0.4p ~ -1.2p로 들쭉날쭉, 평균적으로 mlp 대비 뚜렷한 우위 없음. seed 분산(±0.1~0.3%p)
  안에 들어오는 차이가 대부분.
- **hybrid**: lx/ly(3값 이산)는 6-way 분류, az만 별도 연속 회귀 브랜치로 분리 —
  "cx가 특정 서브태스크에만 온전히 기여하게" 만드는 구조. trackF 조건에서는 mlp보다
  근소하게(+0.3p) 앞섬. bbox_scale 문제와는 직교(az는 bbox와 무관 — 참고용).
- **transformer**(현재 배포 아키텍처)는 오히려 mlp보다 3~6p 낮다 — self-attention이
  260d 프레임 벡터 안에서 vis(256d)가 cx(4d)를 압도해버리는 구조적 약점 존재 가능성.
- **flow**(연속 rectified-flow, MoNa-pi 스타일)는 71%대로 가장 낮음 — 이산 액션 분류
  문제에서 연속 회귀 자체가 손해.
- **bbox_scale**(cx 채널의 절대 크기를 1.0/2.0/3.0배로 스케일)도 이미 재검증 완료
  (`scripts/eval_bbox_scale_phrase_grounder.py`) — 75.55~75.62%로 무영향(CH69 69-6③).

### feature ablation(68챕터, `scripts/ablate_bbox_image_features.py`)과 종합하면

- bbox_only 67.4%±9.8% / image_only 75.6%±0.8% / bbox+image(mlp) 76.7%±1.3%
- bbox 채널을 강조하는 구조(cxgeom, bbox_scale↑)를 다 시도해도 mlp 대비 +0.5p를
  못 넘김 → **"구조를 어떻게 짜든 vis가 이미 cx 정보의 대부분을 함축하고 있어서,
  cx를 별도로 강조해도 얻을 게 별로 없다"**는 가설이 데이터로 뒷받침됨(bbox_only의
  성능 자체가 image_only보다 8p 낮고 분산도 10배 — cx 단독으로는 신호가 약함).

## 아직 안 해본 것 (새로운 방향 후보)

1. **FiLM/gating**: cx로 vis 특징에 곱셈적 변조(scale·shift)를 가하는 구조.
   지금까지는 전부 concat(가산적 결합)만 시도 — cx가 "이 상황에서 vis를 어떻게
   해석할지"를 조절하는 곱셈적 역할은 안 해봄.
2. **cx 시계열 델타(Δcx)를 명시적 입력으로 추가**: 현재 window=6프레임의 raw cx는
   들어가지만, "cx가 커지는 중"인지 "줄어드는 중"인지(방향 전환 시점 판단에 핵심)를
   나타내는 1차 차분은 별도 채널로 넣은 적 없음. 69-6①-b의 F→FR 오판 문제(=지금
   전진해야 하는지 꺾어야 하는지 애매한 경계)와 직결.
3. **cx 전용 auxiliary loss**: 메인 8-class CE에 cx 회귀(또는 R/FR/F 3-way 보조
   분류)를 보조 손실로 추가 — gradient 수준에서 cx 활용을 강제.
4. **bbox_scale을 더 극단적으로**(5.0, 10.0) — 지금까지는 1~3배만 검증, "선형
   스케일로는 안 되지만 훨씬 세게 하면 다를까"는 미검증(가능성은 낮지만 반증 자료 없음).

## 결론 및 권고

과거 실험(cxgeom, hybrid, bbox_scale)은 전부 **"cx 채널을 얼마나 세게/별도로
넣느냐"** 축이었고 효과가 미미했다. 이번에 새로 시도할 가치가 있는 건 **"cx를
vis와 곱셈적으로 결합하거나(FiLM), 시간적 변화율(Δcx)을 추가하거나, 보조 손실로
gradient를 강제하는"** 구조적으로 다른 접근이다. 단순히 "cx 브랜치를 하나 더
추가"하는 식(cxgeom 반복)은 이미 검증된 대로 효과가 작을 가능성이 높다.
