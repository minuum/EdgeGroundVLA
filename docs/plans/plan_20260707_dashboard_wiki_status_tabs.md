> 상태: **승인 완료 (2026-07-07) — 구현 중**
> 확정: 최신현황=스킬 수동 실행 갱신 / 렌더링=`<pre>` 원문 / 위키=핵심요약만

---

## 배경

`docs/` 아래 상태 문서가 20개 넘게 흩어져 있고(`CURRENT_STATUS_*.md`,
`MODEL_STATUS_AND_NEXT_STEPS.md` 등), 세션마다 CLAUDE.md/menemory를 뒤져야
현재 체크포인트·실험 현황을 파악할 수 있음. 대시보드(포트 7800)는 이미
FastAPI + 단일 HTML(`_DASHBOARD_HTML`) 구조로 탭 8개(`switchTab()` 기반)가
있어, 여기에 "보면 바로 아는" 탭 2개를 추가하려는 것.

## 요구사항 (사용자 발화 그대로)

1. **정보용 탭 (위키 역할)** — 프로젝트 개요/구조/핵심 파일/액션 공간 등
   거의 안 바뀌는 참조 정보를 모아서 보여주는 탭
2. **최신 상황 탭** — "스킬로 계속 갱신하는" 탭. 실험 결과, 체크포인트,
   블로커 같이 자주 바뀌는 정보를 최신 상태로 유지

## 설계

### 공통 구조
- 새 탭 2개를 `switchTab()` nav-item 목록에 추가: `📖 위키`, `📡 최신현황`
- 두 탭 모두 **마크다운 파일을 읽어서 렌더링**하는 방식 (하드코딩 HTML 아님)
  → 콘텐츠 갱신 시 대시보드 코드를 안 건드려도 됨
- 대시보드는 JS 마크다운 라이브러리를 안 쓰고 있음 → 가벼운 자체 MD→HTML
  변환(표/헤더/굵게/코드블록 정도만 지원하는 ~40줄짜리 파서)을 새로 작성하거나,
  **간단하게 `<pre>` 모노스페이스로 원문 그대로 보여주는 안**도 가능
  (기존 데이터/문서 스타일이 표 위주라 markdown table 렌더링이 있으면 가독성 ↑)
- 백엔드: `GET /wiki/{name}` 엔드포인트 1개 신설 — `name`은 `info`/`status` 중
  하나로 화이트리스트, 대응 파일을 읽어 `{content, mtime}` 반환

### 탭 1 — 📖 위키 (정보용, 정적)
- 파일: `docs/DASHBOARD_WIKI.md` (신규, 직접 작성/큐레이션)
- 내용: 프로젝트 한 줄 소개, 백본/체크포인트 경로, 액션 8-class 표,
  핵심 파일 경로(학습/추론/평가 스크립트), 알려진 금지사항
  (google-robot generate() 금지 등) — CLAUDE.md 프로젝트 컨텍스트 섹션을
  대시보드에서 보기 좋게 요약한 버전
- 갱신 방식: 수동 (내가 CLAUDE.md 바뀔 때 같이 갱신) — "거의 안 바뀌는 정보"라
  자동화 불필요 판단. 필요시 이후에 자동 동기화로 확장 가능.

### 탭 2 — 📡 최신현황 (스킬로 갱신)
- 파일: `docs/DASHBOARD_LIVE_STATUS.md` (신규)
- 내용: 현재 서빙 중인 체크포인트, 최근 실험(Exp) 결과 요약, 최근 발견/이슈
  (예: 오늘 보낸 flicker 분석), minum 응답 대기 항목, 최근 세션 수/이상 유무
- 갱신 방식: **새 스킬 `.agent/skills/dashboard-status-sync/SKILL.md` 신설**
  - 이 스킬은 "대시보드 최신현황 갱신해줘" 또는 세션 종료/주요 이벤트
    (커밋, 세션 전송, 실험 완료) 시점에 내가 호출 → git log, health, episode_log,
    grounding_analysis 문서를 훑어서 `DASHBOARD_LIVE_STATUS.md`를 다시 씀
  - **주의**: 대시보드 서버(FastAPI)가 스스로 스킬을 실행하지는 못함(Claude
    세션이 있어야 스킬 실행 가능). "실시간 자동 갱신"이 아니라 "내가 스킬을
    돌릴 때마다 갱신되는 파일을 대시보드가 최신 상태로 보여주는" 구조.
  - 대시보드 쪽엔 `최근 갱신: N분 전` 표시 + `🔄 새로고침` 버튼(파일 재fetch만,
    스킬 실행 트리거는 아님) 추가

## 트레이드오프 / 확인 필요한 점

1. **자동 갱신이 아님** — "스킬로 계속 갱신"이 "내가 스킬을 실행할 때마다"인지,
   아니면 cron 등으로 진짜 주기적 자동 실행을 원하는지 확인 필요.
   자동화하려면 `.agent/skills/`가 아니라 별도 cron 스크립트(예:
   `scripts/cron/update_dashboard_status.sh`)로 가야 함 — Claude 세션 없이도
   git log/health 정도는 스크립트만으로 뽑을 수 있지만, "발견/이슈 요약" 같은
   자연어 판단이 들어가는 부분은 스크립트만으론 못 함.
2. **마크다운 렌더 방식** — 자체 경량 파서 vs 그냥 `<pre>` 원문 표시. 후자가
   구현 리스크 없음 (기존 코드베이스에 md→html 처리 로직이 없어서 스타일
   맞추는 데 시간 더 듦). 표가 많으므로 최소 표 렌더링 정도는 있으면 좋을 듯.
3. **위키 탭 초기 콘텐츠 범위** — CLAUDE.md 전체를 옮길지, 핵심 요약만 넣을지.
