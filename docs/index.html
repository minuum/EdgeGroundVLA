Abstract

Grounding, not language modeling, is the bottleneck

Recent mobile-robot navigation research has pushed toward language-instructed navigation with large Vision-Language Models, exemplified by Mobility VLA. But VLM-based inference is computationally heavy and depends on pre-built infrastructure — demo-tour videos and offline topological graphs — which limits deployment on resource-constrained platforms.

EdgeGround-VLA takes a different path. It fuses the representations of two vision encoders with distinct grounding characteristics — OWLv2 for real-time open-vocabulary object localization, and Kosmos-2's vision encoder for phrase-grounded visual features — and combines them with a lightweight MLP action head that outputs one of 8 discrete movement classes, mapped to a 3-DoF command via a fixed lookup table. Both backbones stay frozen; only the 0.866M-parameter action head (plus a 0.262M projection layer) is trained. Deployed on a Jetson Orin NX with no cloud connectivity, the system reaches a 95.0% goal-reaching success rate across 100 real-world trials — above the 86–90% end-to-end success Mobility VLA reports in comparable settings. Decomposing the pipeline by component further shows that OWLv2 grounding alone accounts for ~97% of inference latency, identifying exactly where future compression effort (quantization, distillation) should go when porting to platforms as constrained as a Raspberry Pi.

Method

Heterogeneous grounding, fused behind a frozen backbone

A 1280×720 RGB frame is processed in parallel by two independently pre-trained, frozen encoders — one built for detection, one built for phrase grounding — and their outputs are concatenated into a single 260-dimensional frame feature.

The action space is deliberately discrete: 8 classes covering stop, forward, lateral strafe (×2), diagonal strafe (×2), and in-place rotation (×2) — well matched to the robot's 3-axis omni-wheel (Kiwi-drive) chassis, which can move laterally without rotating. Continuous regression or diffusion/flow-matching action experts were considered and rejected: they typically need far more demonstration data than this project's 225-episode dataset provides.

Training

Stage 1 generalizes cleanly; Stage 2 shows the expected imitation-learning gap

image_proj (Stage 1) trains to near-identical train/validation accuracy. The action head (Stage 2) shows a much larger train–validation gap — a well-documented pattern in teleoperation-based imitation learning, and one that episode-level closed-loop control is structurally able to correct for.

Validation accuracy is a lower bound on real-world competence, not a ceiling on it.

Frame-level scoring can't credit re-decision; closed-loop control can.

Why does a 17.4-point gap not translate into a 17.4-point drop in real-world success? Two reasons. First, frame-level validation accuracy asks whether the model matches the single action the human happened to choose; at any given moment, several actions can be equally valid (e.g. FORWARD and FWD+LEFT both make progress when the target is slightly left). Second, the robot re-observes and re-decides at every timestep — an average of 11.64 decisions per successful episode — so a substitutable frame-level "error" gets corrected on the very next frame. Deployment

The bottleneck is grounding — not the model doing the reasoning

Decomposing end-to-end latency by pipeline stage reveals a counter-intuitive result: the smaller model is the slower one.

OWLv2 grounding (fp32)
1901.7 ms · ~97%
OWLv2 grounding (fp16)
962.1 ms
Kosmos-2 vision encoding
53.7 ms · ~3%
MLP action head
<1 ms · ~0%

OWLv2 (0.155B params) is responsible for ~97% of end-to-end latency, while Kosmos-2's vision encoder — nearly twice as many parameters (0.303B) — accounts for only ~3%. Parameter count alone does not predict inference latency; OWLv2's cost comes from cross-attention text-query matching and multi-scale anchor processing, not raw FLOPs. Switching OWLv2 to fp16 cuts its latency by ~49% (1901.7ms → 962.1ms), confirming that compressing the grounding stage — not the policy — is where future work should focus when porting to platforms as constrained as a Raspberry Pi.

End-to-end pipeline latency is ~1.96s (fp32) or ~1.02s (fp16) — far from the tens-of-milliseconds a continuous controller would need. But EdgeGround-VLA doesn't need continuous control: it updates a discrete action periodically, re-issuing the last decided command at 10Hz between grounding updates so the robot never actually stops waiting. The 95% real-world success rate is the direct evidence that this control scheme is practical for goal-reaching.
