# 분석: 컨트롤러 환경 차이 — 수집(조이스틱)과 추론(서빙)이 로봇을 실제로 움직이는 방식 (2026-10-23)

사용자 지적: "이동 궤적 자체는 맞는데 회전의 물리 환산·타이밍과 컨트롤러 환경 차이가 원인일 수 있다." 코드(`vla_control_utils.py`, `mona_dashboard.py` 조이스틱·구동 루프)와 데이터 속성을 대조했다.

## 1. 가장 중요한 발견: 하드웨어는 명령 '크기'를 쓰지 않는다
`publish_and_move`의 하드웨어 경로:
- `|az| > 0.1` → `driver.spin(sign(az) × rot_throttle)` — **az 크기 무관, 부호만**
- 그 외 이동 → `driver.move(int(atan2(ly,lx)°), throttle)` — **(lx,ly) 크기 무관, 방향각만**
→ 물리 동작은 (방향각 | 회전 부호) × throttle 로만 결정된다. 서버가 내는 단위방향×1.15, 모델 크기, az 0.25/0.4/0.7/1.0 같은 숫자는 로봇에 영향이 없다.
→ **정정**: 이전 분석(`analysis_20261023_rotation_physical_motion.md`)의 "az 단위·초당 효과가 로봇이 4배"와 "az=clip(|cx−0.5|/0.83, …) 비례 회전"은 물리적으로 의미가 없다. 비례 회전은 az 크기가 아니라 **throttle_scale 또는 버스트 시간**으로 해야 한다.

## 2. 학습 라벨의 '속력'은 물리 속도가 아니다
- 300개 전 에피소드 `joystick_speed_setting=1.15`, `drive_mode=C_3level_speed`. `set_speed`는 throttle=round(1.15/1.15×50)=**50 고정**, `rot_throttle=17.5`.
- `actions_raw`는 스틱 아날로그값(예: 0.05, 0.35), `actions_exec`의 0.4/0.7/1.0은 그 크기에서 **파생한 3단계 라벨**. 사람이 낸 물리 속도는 항상 throttle 50(직진 약 26.4 cm/s 보정값), 회전은 17.5로 일정했다.
- 그래서 모델이 학습한 "속력 3단계"는 물리 속도 정보가 아니고(데이터 해부의 속력 분포 24/52/24%도 스틱 크기 분포), `speed_source=model`(모델 크기로 속력 선택)은 학습 물리와 연결되지 않는다.

## 3. 학습 물리 vs 서빙 물리(설정 차이)
| 항목 | 수집 | 추론(현재 설정) | 차이 |
|---|---|---|---|
| 직진 throttle | 50 | 50 × speed_scale 0.7 = 35 | **서빙이 30% 느림**(약 26.4 → 20.6 cm/s) |
| 회전 throttle | 17.5 | 17.5 × 0.7 = 12 | 30% 느림 |
| 구동 방식 | 조이스틱 async 10Hz 연속 발행(스틱을 쥐는 동안) | SYNC: 0.4초 버스트 후 정지(주기 약 1.55초) / ASYNC: 직전 명령 유지 | 시간 구조 다름 |
| 방향 | atan2(ly,lx) 각도 | 같음(int 도 단위) | 동일 |
| 램프 | 없음 | 회전 명령 첫 램프 단계에서 az×0.33<0.1 → 약 17ms **전진 펄스**(angle=atan2(0,0)=0) | 작은 버그 |
(추론 세션의 실제 `ctrl.throttle`은 로그에 없다 → 스냅샷에 추가 필요.)

## 4. 회전 타이밍 — 측정(Δcx = 타깃 cx 변화, 화각 미확인)
- 사람(학습): 연속 회전 구간 평균 0.52초(301구간), **−0.296/초(az>0), +0.317/초(az<0)**, 프레임 간격 0.128초.
- 로봇 SYNC 버스트(0.4초 + 다음 관측까지 정지): **−0.207/버스트 = 0.52/초(az>0)**, +0.15~0.30/버스트(az<0, n=5).
→ 로봇이 낮은 throttle(12 vs 17.5)인데도 **단위 시간당 회전이 약 1.75배 크게 관측된다**. 가능한 원인(미구분): (a) 정지 명령 뒤 관성·카메라 지연이 버스트 관측에 포함, (b) 스핀 명령이 연속 발행(수집)과 단발+타이머(추론)에서 구동기 쪽 동작이 다름, (c) throttle→각속도가 비선형. 직접 보정 실험이 필요하다.

### 4.1 영상 기반 재측정(bbox 불필요, `scripts/analyze_rotation_odometry.py`)
인접 프레임의 수평 이동을 위상 상관으로 계산(위쪽 벽 영역, px@폭 320):
| | 학습(사람 연속 회전) | 실기 SYNC 버스트(0.4초) |
|---|---|---|
| 회전 한 번의 총 이동 | az>0: −55px(0.55초, n=94) / az<0: +53px(0.50초, n=66) | az>0: **−68px**(n=20) / az<0: **+69px**(n=5) |
| 초당 이동 | 약 95~103 px/s | 약 170 px/s (0.4초 가정) |
| 정지 후 잔여(다음 idle 스텝) | — | −14px(버스트의 약 21%, n=5) / +5px(n=1) |
→ bbox 기반 결과(약 1.75배)와 일치. 로봇은 throttle이 낮은데(12 vs 17.5) 단위 시간당 회전이 약 1.7배 → **버스트의 실제 회전 시간이 0.4초보다 길거나**(램프·정지 패킷·구동기 지연) 구동기 반응이 연속 발행과 단발 명령에서 다를 가능성. 한 번의 버스트(−68px)는 사람의 시작 회전 한 번(−55px)의 1.2배라 시작 회전 재현용으로는 크기가 비슷하다. 정지 후 잔여는 버스트의 약 20%.

## 5. 이동 궤적 자체가 맞는지
학습 특징 공간의 최근접 학습 프레임이 가진 사람 방향과 모델 예측을 라이브 프레임에서 비교하면 중앙값 8.6°(평균 19.7°)로 일치: 모델은 장면 → 학습 행동을 재생한다. 즉 의도한 궤적은 학습과 일치하고, 어긋남은 (i) 타깃 서보 부재와 (ii) 위 물리 환산 차이(속도 30% 낮음, 시간 구조, 회전 정지 특성)로 나뉜다.

## 6. 반영·제안
1. **구현 완료(기본 끔)**: 타깃 서보 `VLA_EGVLA2_SERVO_BLEND`(0=끔, 1=서보 단독 방향)·`SERVO_K`(2.0)·`SERVO_MAX`(0.7). 방향각만 바꾸므로 하드웨어 동작에 유효. 테스트 18개 통과.
2. **속도 정렬 비교군**: speed_scale 1.0(throttle 50, 학습 물리와 동일) 대 0.7(현재). 드라이런 후 안전 확인하고 시험.
3. **로그 보강**: `ctrl.throttle`, `rot_throttle`, 실제 호출 `driver.spin/move` 인자, 구동 모드 값을 스냅샷·스텝 로그에.
4. **회전 보정 실험(로봇)**: 정지 상태에서 {rot_throttle×scale 0.5/0.7/1.0} × {0.2/0.4/0.6초 버스트}를 각 5회, 전후 cx(또는 각도기)로 환산. 비례 회전은 이 결과로 throttle_scale 또는 버스트 시간 조절식 확정.
5. **램프 전진 펄스 수정**: 순수 회전은 램프를 건너뛰거나 az 램프 하한을 0.1 이상으로.
6. **SYNC vs ASYNC 회전 비교**: 같은 회전을 두 모드로 시험(타이밍·관성 분리).
