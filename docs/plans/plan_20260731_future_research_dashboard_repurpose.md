# 미사용 대시보드 탭의 Future Research 재활용 계획

> 작성: 2026-07-31 (soda)
> 배경: 100개 스크리닝 완료 후, 축적된 128세션 factor 분석 + 대시보드 13탭 전수 조사 결과를 결합

---

## 0. 왜 지금 이 계획인가 — 핵심 발견이 방향을 정해줌

128개 세션 전체를 분석한 결과, **성패를 가르는 factor는 사실상 하나**로 수렴했습니다.

### 발견 1: 그라운딩 신뢰도가 유일한 병목

th=0.20 조건(설정 통제)에서:

| grounding 성공률 | 주행 성공률 |
|---|---|
| **gnd% >= 80%** | **69/69 = 100.0%** (95% CI 94.7~100%) |
| gnd% < 80% | 21/32 = 65.6% |

**타겟을 안정적으로 보고 있으면 정책은 단 한 번도 실패하지 않았습니다.** 128세션의
모든 실패는 예외 없이 gnd% 80% 미만 구간에서만 발생했습니다.

### 발견 2: threshold가 그 병목을 직접 움직임 (위치 통제 후에도 유효)

| 위치 | th=0.25 | th=0.20 | 차이 |
|---|---|---|---|
| 강좌 | 4/10 (40.0%) | 16/20 (80.0%) | +40.0%p |
| 약좌 | 3/17 (17.6%) | 17/21 (81.0%) | +63.3%p |
| **합계** | **7/27 (25.9%)** | **33/41 (80.5%)** | **+54.6%p** |

Fisher exact **p = 1.15e-05**, 신뢰구간 겹침 없음.

인과 경로: `threshold 0.25→0.20` → `평균 gnd% 66.5%→81.9%, 완전미검출 세션 22%→3%`
→ `주행 성공률 25.9%→80.5%`

### 발견 3: 좌우 비대칭은 아직 유의하지 않음

좌측 32/40(80.0%) vs 우측 37/40(92.5%), Fisher **p = 0.193** — 경향성 수준.
표본을 늘리기 전엔 단정 금지.

### → 연구 프레이밍 전환

이 결과는 "VLA 정책 성능 보고"보다 **"인지-정책 병목 분리(perception-policy
bottleneck decomposition)"** 프레이밍이 훨씬 강합니다:

> decomposition 구조에서 MLP 정책 헤드는 이미 충분히 학습됐고(grounding만 되면
> 100%), 실기 성능의 전부는 open-vocabulary detector의 신뢰도가 결정한다.
> threshold 하나로 25.9%→80.5%가 움직인다.

**그리고 지금 죽어있는 탭/미시각화 데이터가, 정확히 이 주장을 뒷받침할 계측기입니다.**

## 2. Future Research 재활용 계획

### 🔴 Tier 1 — 논문 주장을 직접 뒷받침 (우선)

#### T1-1. `grounding` 탭 → **"그라운딩 실패 분석기"로 전면 개편**
현재 verify 탭의 부분집합이라 존재가치 없음. 발견 1/2를 증명하는 전용 화면으로 재활용:
- **confidence 분포 히스토그램** — threshold 선(0.20/0.25)을 겹쳐 그려서 "왜 0.25가
  knife-edge인지"를 한 장으로 보여줌 (논문 Figure 후보)
- **미시각화 데이터 `grounding_caption` 노출** — 실패 시 그라운더가 뭘 봤는지
- **per-frame 검출 타임라인** — 세션 내 has_bbox on/off 스트립, 실패 구간 하이라이트
- threshold 슬라이더로 **저장된 프레임을 재판정**(오프라인 re-scoring) → 실기 재수집
  없이 threshold-성능 곡선을 뽑을 수 있음

#### T1-2. `latency` 탭 → **Chart.js 인프라 회수 + 그라운딩 시계열로 전환**
- 먼저 **Chart.js CDN 의존 제거**(로컬 번들 인라인) — 현재 오프라인에서 깨져있을
  가능성 높음. 앱 전체에서 유일한 차트 인프라라 회수 가치 있음
- 차트 대상을 drift에서 **gnd% / confidence over time**으로 교체
- 기존 drift 기능은 유지하되 `logs/drift_sessions/` 과거 조회 뷰어 추가

#### T1-3. `action_history` → **궤적 플롯 + FPE 자동 계산**
지금 FPE(최종 위치 오차)를 **사람이 눈대중으로 입력**하고 있음. `action_history`를
적분하면 궤적 추정치가 나오므로:
- 궤적 오버레이 시각화(논문 Figure 후보 — 성공/실패 궤적 대비)
- FPE 자동 추정 → 수동 입력 편차 제거, 라벨링 시간 단축

### 🟡 Tier 2 — 데이터 신뢰성 (논문 방어용)

#### T2-1. `dataset` 탭에 `flagged_model_issue` 노출/필터 (작업량 최소, 가치 높음)
"학습에서 제외해야 할 에피소드" 표시가 사후에 안 보임 → 데이터셋 위생 문제.
타일 + 필터 칩 추가만 하면 됨.

#### T2-2. `frame_duplicate_warning`을 인스펙터 이상감지 목록에 통합
카메라 멈춤이 실기 실패의 교란요인인데 현재 사후 확인 불가.

#### T2-3. 실험용 CSV 뷰어
`episode_log_experimental.csv`를 볼 화면이 없어서 기록이 사장됨.
verify 탭 테이블에 소스 토글 추가.

## 3. 다음 실험 제안 (Tier 1이 열어주는 것)

1. **threshold 스윕 (오프라인)** — T1-1의 re-scoring으로 저장된 128세션 전 프레임을
   0.10~0.35 스윕 → 실기 재수집 없이 threshold-검출률 곡선. **비용 0**
2. **동일 위치 설정 A/B** — 현재 commit×위치 교란으로 회전수정/force_reground 효과가
   검증 불가. 강좌 또는 약좌 한 위치를 고정하고 on/off 각 20개
3. **좌우 비대칭 검증** — p=0.193이라 유의하지 않음. 좌측 표본 추가 수집 필요
4. **held_success 30.3% vs 실기 89% 격차** — 오프라인 지표가 실기를 심하게 과소평가.
   minum 측 확인 요청 중
