# 발견: 에피소드 시작의 "제자리 회전"을 서빙이 버린다 (2026-10-22 밤, 로봇 첫 프레임 관측 + 데이터 분석)

## 1. 현상 (로봇 세션 보고)
/reset 직후 첫 프레임(bbox cx=0.758, area=0.026, 학습의 weak_right 구도): `chunk_first (lx,ly,az) = (0.008, 0.003, 0.438)`, `model_magnitude=0.0084`. 서버→대시보드→로봇 전달 경로에 변형 없음, 두 세션(19:45, 20:12) 재현.

## 2. 원인: 모델은 정상이고 서빙이 az를 버림
학습 데이터(300 에피소드, 29,161 프레임) 분석:
| 항목 | 값 |
|---|---|
| 에피소드 시작이 제자리 회전(\|lx,ly\|<0.2, \|az\|>0.2)인 비율 | **53.7%** (연속 중앙값 5프레임, p90 6프레임 ≈ 0.6~0.8초) |
| weak_right·strong_right의 첫 프레임 사람 조작 | lx,ly=0, az=+0.4(우측 목표에서 먼저 돌고 출발) |
| 시작 10% 구간의 프레임 구성 | 회전만 27%, 이동 66% (전체 평균 회전만 5.7%) |
| 모델 첫 프레임 예측(in-sample) | 회전 강함(az 0.29~0.44), \|lx,ly\| 작음 → 데이터 그대로 |
| 회전 프레임에서 모델 az 부호 일치 | 88% (크기는 과소: 모델 중앙값 0.29 vs 사람 0.70) |
서빙 쪽: `to_drive_command(use_az=False)`가 az를 0으로 만들고, 크기 <0.2이면 `stop`으로 처리, 단독 서버 상태기계는 stop 3프레임 연속이면 **STOPPED 래치(에피소드 종료)**. in-sample 시뮬: 시작 15% 안에서 래치가 걸리는 에피소드 **약 63%**.
→ 지금 설계(az=0 첫 적용)로는 시작 회전이 필요한 에피소드의 절반 이상에서 로봇이 출발하지 못하거나 시작하자마자 정지한다. (EGVLA1은 STOP/ROT 판단을 기존 판단이 맡았고, 단독 서버(단계 B)는 이를 대체해야 하는데 az 처리가 빠져 있었다.)

## 3. 오프라인 지표가 못 본 이유
방향 오차는 사람·모델 둘 다 이동 중인 프레임(\|lx,ly\|>0.2)만 비교한다. 회전만 하는 프레임(전체 5.7%, 시작 구간 27%)은 평가에서 빠졌고, GO/STOP F1은 회전을 STOP으로 묶어서 F1 0.95로 정상처럼 보였다.

## 4. 제안(구현 승인 전)
1. **회전 상태 추가**: 정책 출력이 \|lx,ly\|<0.2이고 \|az\|>임계(0.2)면 STOP이 아니라 ROTATE: lx=ly=0, az=부호(az)×회전 크기(기존 ROT 0.25 또는 min(\|az\|,0.4)), 속도 규칙은 회전용 고정값. stop 디바운스·래치에 세지 않음.
2. **회전 종료 조건**: 이동 성분이 0.2를 넘으면 DRIVE로 복귀, 연속 회전 상한(예: 12프레임≈1.5초, 사람 p90의 2배) 초과 시 STOPPED가 아니라 경고 후 DRIVE 시도. 회전 중에도 near_area·소실 규칙은 유지.
3. 크기 과소(0.29 vs 0.70)는 부호만 쓰고 크기는 고정하는 안이 안전. 모델 az 크기 보정은 후속.
4. 평가 보강: 회전 프레임 분류(회전/이동/정지 3클래스)와 az 부호 일치율, 시작 구간 래치 시뮬을 오프라인 표준 지표에 추가. 
5. 실기 확인: 로봇 세션이 이미 가진 az 적용 경로(`is_rotation`, 0.4초 버스트)가 단계 B 응답의 `action_3d`로 동작하는지 드라이런에서 확인.

## 5. 오늘 폐루프에 대한 영향
현재 단계 B 단독 서버 상태기계는 시작 회전을 처리하지 못해 폐루프가 시작되지 않을 가능성이 크다. 선택지: (a) 회전 처리를 넣은 뒤 폐루프(권장, 변경이 작음), (b) 사람이 출발 전에 목표 쪽으로 돌려놓고 시작(임시), (c) 시작 구도를 중앙(center)만으로 한정. 결정 필요.

### 6.1 부호 규약 (정정: 데이터 규약 = 로봇 실행 규약)
- 학습 데이터: 시작 회전 에피소드에서 az>0이면 회전 후 타깃 cx가 줄어드는 비율 99%(86개), az<0이면 늘어나는 비율 100%(75개) → 기록 az **+ = 우회전**.
- **실기 확인(2026-10-22 20:30, 로봇 세션)**: 타깃 cx=0.758일 때 az=-0.25를 보냈더니 cx가 0.5 쪽이 아니라 반대로 밀려남 → 이 로봇에서 **-az = 좌회전, +az = 우회전**. 즉 기록 규약과 실행 규약은 같다.
- 처음 구현(b292d582)은 '로봇 규약 + = 좌회전'(ROS 관례, EGVLA1 ROT_L=+0.22 해석)을 가정하고 부호를 뒤집어서 **반대로 돌았다.** 정정: 타깃이 오른쪽(cx>0.5)이면 +az, 왼쪽이면 -az. 소실 탐색 방향도 같은 규약으로 바꿈(마지막 cx<0.5면 -az). cx를 모르면 모델 az 부호 그대로.
- ⚠️ 소실 탐색 방향과 시작 회전을 모두 실기 드라이런에서 사람이 눈으로 확인.
