## 2. 핵심 분석 요약 (왜 오른쪽으로 쏠렸는가?)

### 원인 A: 그라운딩 장기 상실 (PaliGemma2 학습 편향)
- **현상**: 세션 전체 15스텝 중 **13스텝(86.6%)에서 그라운딩이 완전히 상실**되었습니다.
- **원인**: `obj_right` 시나리오 특성상 목표물(바구니)이 오른쪽 변두리(`cx > 0.7`)에 위치하게 되는데, PaliGemma2 모델의 학습 데이터 중 `cx > 0.7` 분포가 전체의 **7.8%**에 불과해 극심한 오른쪽 실명 현상이 일어납니다. 이로 인해 모델이 화면 전체(`full-frame`)를 잡거나 화면 맨 위(`top`)를 그라운딩하는 오탐을 연발했습니다.

### 원인 B: Fallback 관성에 의한 조향 발산 (Oscillation)
- **현상**: 그라운딩을 상실한 상태(`has_bbox=False`)에서 기본 Fallback 좌표인 `cx=0.5, cy=0.6`이 서버에 주입되었습니다.
- **거동**:
  1. 초반 1~8스텝 동안 모델은 과거 히스토리(W=6) 상에서 우측 편향을 극복하기 위해 `FWD+L` (왼쪽)을 뱉기 시작했습니다.
  2. 과거 윈도우에 `FWD+L` 이 연속으로 누적되자, 9스텝부터는 다시 중심을 맞추기 위해 `RIGHT` (오른쪽) 액션을 뱉으며 크게 지그재그(Oscillation)를 그렸습니다.

### 원인 C: 복귀 루프(`_return_loop()`) 역재생 휠 슬립 누적
- **복귀 계산 메커니즘**: `rev = [(-lx, -ly, -az) for lx, ly, az in reversed(history)]`
- **주행 시 누적 벡터**: `FWD+L` (linear_y = 1.15) 8회, `RIGHT` (linear_y = -1.15) 6회 수행
- **복귀 시 역벡터**:
  - 초반에는 주행 시의 `RIGHT`의 역벡터인 **`LEFT` (linear_y = +1.15)로 복귀**를 시도.
  - 후반에는 주행 시의 `FWD+L`의 역벡터인 **`FWD+R` (뒤로 가며 오른쪽으로, linear_y = -1.15)로 복귀**를 수행.
- **물리적 요인**:
  - 로봇이 뒤로 가며 오른쪽(`FWD+R`)으로 역주행할 때, 메카넘 휠 및 모터 하드웨어의 후방 구동 슬립(slip) 비대칭성으로 인해 왼쪽 방향 보정은 덜 가고 오른쪽 방향 밀림이 지배적으로 작용하여 오른쪽으로 치우쳐 쏠리게 되었습니다.

## 3. 대응 방안 및 결론
1. **모델 편향(VLM 문제) 해결**: `obj_right` 시나리오의 탐지 성능을 보완하기 위해 `cx > 0.7` 분포의 우측 영역 바구니 데이터를 보강한 LoRA 파인튜닝이 다음 개발 단계에서 강력히 요구됩니다.
