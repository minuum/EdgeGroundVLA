## 3단계 — 로봇을 움직이지 않는 확인 (API만, 서버에 모델 1개만 로드)
1. 동환이 운영서버를 정지하고 해당 체크포인트 하나만 로드해 기동(운영서버 위에 추가 로드 금지 — Jetson 리부팅 전례). **기동 방식은 동환 결정.**
2. `/health`에서 `ckpt`·`ckpt_sha256`이 SHA256SUMS와 같은지, `phrase_from_request: true`인지 확인(재시작·`switch_family`마다 꺼지므로 매번).
3. 저장된 11/13 H5 프레임(의자·가운데 `20261113_170121`, 바구니 `20261113_150911`, 화분 `20261113_151741` 등)을 `/predict`에 보내 응답만 기록(**대시보드의 주행 루프는 시작하지 않는다**). 기대: a3-s2는 의자·가운데에서 움직임 명령, 바구니는 A3와 같은 방향. 오프라인 재생과 비교해 서빙 경로 동등성도 확인.
4. 이상(응답 오류, 해시 불일치, 지시어가 안 먹음)이 있으면 **중단하고 보고**.

## 4단계 — 구동 시험 (동환 입회, 단계마다 승인, 운영자 수동 정지 상시 가능)
- 순서: ① 바구니 G3 ×3(정상 주행 확인) → ② 의자 G3 ×5 → ③ 책상 G3 ×5 → ④ 화분 G3 ×5 → ⑤ 옆 위치 점검(의자 G4 ×3, 책상 G2 ×3). ①이 어긋나면 이후 중단.
- 지시어는 11/13과 같은 문구로 고정(문장형 `go to the gray basket`, `go to the brown wooden chair`, `go to the small desk`, 단어형 `flower pot`).
- **시험 전에 성공 기준을 한 줄로 정해 기록**(예: 물체 앞 어느 거리 안에서 정지). 11/13은 기준 없이 operator 판정이었다.
- 가능하면 운영자에게 체크포인트를 알리지 않는다(11/13은 비맹검).
- 세션마다 H5 외에 **세션 JSON(`inference_reports`)을 보존**(원출력 `action_cont`·`chunk_first` 포함).
- 개선 판단: a3 기준선과 Wilson 95% 구간이 겹치면 "개선"이라고 쓰지 않는다(가운데 기준선 25~61%).
